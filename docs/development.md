# 开发参考

本文说明模块边界、数据约定、控制时序和设备接口。安装与操作见 [README](../README.md)，采集格式见[数据采集参考](recording_reference.md)。

## 模块

- `devices/`：设备连接、收流、单位转换和驱动保护。导入模块不加载设备 SDK，显式创建或启动设备时才加载。
- `control/arm/`：Quest 映射、滤波、插值和受约束的笛卡尔伺服。
- `control/hand/`：重定向、手势和手部运行进程。
- `control/combined.py`：协调接合、暂停和回位。
- `cli/runtime.py`：两个遥操作入口共用的终端 UI 和调度。
- `common/runlog.py`：结构化运行日志。
- `recording/`：相机采集、原始写盘、离线整理、审片和 DP 转换（含质量检查）。离线部分按职责分层：
  - `schema.py` 定义流、字段、相机和分辨率，`episodes.py` 定义条目状态和递归发现；其他模块不再写死这些值。
  - `dataset_manifest.py` 管理 session 根目录的任务、机器人、输入设备、相机角色和 episode 相对路径索引；创建与恢复时由录制后台更新，离线整理结束后核对索引。动态状态和标定快照仍归各条 `episode.json` 管理。
  - `timeline.py` 是纯 numpy 的对齐原语、暂停识别和时间网格，不读 zarr 和视频。
  - `policy.py` 把 strict 和 repair 表达为同一种 `ConversionPolicy`，未指定配置时读 `configs/recording_conversion.yaml`（repair）；`plan.py` 按策略为一条数据生成 `EpisodePlan`（查询时刻、相机匹配、逐原因的有效性、片段、暂停，以及报告要用的各路原始时间），不写盘。
  - `quality.py` 从计划生成帧数去向（首尾裁剪、中间剔除、缺帧复用、放宽插值、暂停）和原始流健康统计，按 `configs/recording_quality.yaml` 定级，并做跨条目元数据比较；`convert.py` 遍历条目，dry-run 与正式转换走同一流程，正式转换才解码、写 zarr 和原子发布。
  - `review.py` 读写 `review.json` 并生成预览。
- `cli/`：大多数命令行入口；`scripts/` 下同名文件只是薄包装。点动入口在 `control/arm/jog.py`，Hand2 回零在 `control/hand/home.py`，`scripts/analyze_tianji_ik.py` 自身就是完整实现。
- `visualization/`：只读查看器和 RealSense 显示。
- `tests/support/`：模拟设备、样本和时钟；`recording.py` 构造带真实编码视频的原始条目，可模拟丢帧、暂停、频率异常和元数据差异。转换输出由 `tests/test_recording_golden.py` 锁定，确需改变输出时用 `python -m tests.test_recording_golden --regenerate` 重新生成基线。

## 数据约定

Python 空间量使用米、弧度和秒，四元数顺序为 XYZW。`SampleHeader` 保留流、epoch、序号、接收时间、来源时间和有效性；不同设备的来源时钟不能直接相减。无效或缺失观测保持 `None`，不能补零伪造有效值。

`OperatorInput` 聚合手腕输入，`RobotState` 聚合工具实测位姿，`RobotTarget` 聚合工具目标及来源引用、创建时间和到期时间。手套骨架与 Hand2 关节命令使用设备专用类型。`Submission.accepted` 只表示提交被接受；`CommandEvent` 的发送结果不表示机器人已到位。

## 控制生命周期

构造运行器和 `start()` 只启动连接与收流，`engage()` 才接合。机械臂使能前校验运动学和约束，使能后用驱动保存的实际接合样本重建伺服基准。组命令全部提交成功后才推进伺服状态；暂停、取消或异常后不得提交迟到的求解结果。

机械臂循环 200 Hz，手部默认 120 Hz。Hand2 关节状态和诊断的推送频率由 `feedback_hz` 指定（默认把原生 1000 Hz 限为 200 Hz），两路必须请求相同值，设备实际量化结果写入状态日志。

期限：Quest 控制输入 100 ms；机械臂命令提交 50 ms，包含生成、求解和等待 SDK 接受，读取缓存或循环重试不续期。天机驱动另有 80 ms 看门狗（比 50 ms 多一个慢周期）：两次被接受的目标之间或某侧反馈序号停滞超过 80 ms 即暂停。接合模式确认有独立的启动期限，确认后恢复普通期限。慢周期跳过错过的调度点，不补发成串旧动作。

联合控制用 `spawn` 创建 Wuji 子进程，SDK、设备接收和手部控制循环都在子进程内；主进程只交换生命周期请求和观察快照（保留原始来源时间），不转发逐帧关节命令。父进程心跳超时使子进程暂停；子进程、骨架、诊断或控制线程失联使主进程判定异常。恢复须显式重新接合。

追踪无效、坐标原点变化、选中侧反馈异常、控制模式变化或期限超时都会暂停，运动故障不会因下一包有效反馈自动清除。观察者发布失败会锁存为设备故障；录制观察者例外，它自行处理内部错误，只作废当前采集条目。

## 天机官方 SDK

随包 SDK 的来源、内容和更新方法见 [SDK 说明](../bimanual_teleop/vendor/tianji/README.md)。

`devices/tianji/sdk.py` 负责路径、完整性和类型检查，以及官方接口的成组提交。官方封装的问题只在适配层修正：整数参数使用 Linux `c_long`；`OnGetBuf` 填充官方 `DCSS`，避免转字典时截断到四位小数。传输协议和收发线程仍由厂家库管理。

一个 `ControlSDK` 持有双臂连接，命令构造由互斥锁串行化，使用官方 `clear_set`、参数／目标接口和 `send_cmd`。等待可用槽最多 5 ms 且不超过目标有效期；构造前、等待中和提交前都检查期限与取消，构造失败的未提交内容会被清空。配置、接合、回位和下伺服依赖新反馈确认，控制循环不等待同步应答。

### 观察与命令状态

- `SDK_SUBMITTED` 只表示官方 API 接受了命令，不表示 UDP 已发送、控制器已接收或动作已完成。驱动不发出 `SENT`，也不伪造发送时间、errno、字节数或丢包统计。
- `received_monotonic_ns` 是主机观察到新反馈快照的时间，`packet_index` 是本地快照编号，都不是底层收包时间或 UDP 包计数。
- 反馈序号逐侧检查，重复读到同一缓存不刷新有效期。SDK 只暴露最新快照，序号跳变不能判定为网络丢包。
- 官方库不提供待发命令取消或发送前期限拦截：已交给 SDK 的命令可能在期限后发出，暂停或退出无法撤回。
- `tianji.motion_stop.v1` 保留历史字段 `last_native_call` 供诊断兼容，内容为最近一次 `ControlSDK` 操作名（如 `submit`、`configure`）和主机调用耗时，不是厂家 C 接口名。

### 单位、模型与运动学

官方关节输入／反馈为度，FK／IK 矩阵平移为毫米；几何雅可比已是 SI 单位（线性行 m/rad、角速度行 rad/rad），不能再除以 1000。

`TianjiKinematics` 使用 `Marvin_Kine` 的 FK、IK、雅可比和零空间接口，双侧初始化与求解共享运动学锁。法兰位姿相对各自基座。模型固定为 M6 4.0，`--model` 只能指向相同内容的文件。离线 IK 分析只加载 `libKine.so`，复用同一求解逻辑。

### 回位、暂停与退出

- **配置与接合**：等待刚度、阻尼、工具和阻抗坐标方向的 float32 反馈，以及速度比例、加速度比例和力控类型的整数反馈全部匹配；笛卡尔接合要求新反馈 `state=3`、`impedance_type=2`，位置模式接合要求 `state=1`。
- **回位**：先用实测关节切入位置模式，确认 `state=1` 后发送最终目标；到位要求新的低速反馈、匹配的 float32 目标且关节误差 ≤ 0.5°。
- **暂停**：笛卡尔暂停保持实测关节；位置运动用官方 RSTA 参数中止。只有停止请求被拒且新反馈仍在位置模式时，才改用实测位置保持。
- **清错**：查询所选侧七个伺服错误码，对故障侧执行一次 RESET，至少等待 200 ms 并由新反馈确认；不使能、不运动。
- **退出**：禁止新运动提交，只对曾受控的一侧请求下伺服，最多等待 2 s，直到收到 IDLE、零错误、低速标志为 1 且关节速度 ≤ 0.5°/s 的新反馈。只读连接不下伺服。未确认时报告失败；通信中断时无法确认物理状态。

## Quest 协议

[原生客户端](../quest_app/src/main/cpp/quest_capture.cpp) 通过 `QuestCapture` logcat 标签输出逐行 JSON（协议 `v=1`），Python 接收器按启动会话过滤。

`frame` 字段：

| 字段 | 含义 |
| --- | --- |
| `session`、`seq`、`origin` | 启动会话、帧序号和参考空间代次 |
| `query_ns`、`xr_time`、`send_ns` | 设备单调查询时刻、对应的 OpenXR 时刻和输出时刻 |
| `state`、`refresh_hz` | XR 会话状态和显示刷新率 |
| `head`、`left`、`right` | 同一查询时刻的头显和 grip 位姿 |
| 位姿中的 `p`、`q`、`flags`、`active` | 米、XYZW 四元数、OpenXR 有效／追踪标志、手柄动作是否活跃 |

OpenXR 坐标为右、上、后，Python 转为前、左、上：`(x, y, z) → (-z, -x, y)`，旋转作相同基变换。位置或方向缺失时各自保持缺失，不互相推定。

`event` 包含设备时间、事件名和详情，报告会话状态、刷新率、错误和参考空间变化。参考空间变化按 OpenXR 生效时间切换代次，期间主机阻止接合。设备时钟与主机未同步，接收器同时保留两种时间，不以差值表示单向延迟。

接收器 1 s 无新帧报告收流异常；控制层另有 100 ms 输入期限和积压检查。协议不重传旧帧，恢复收流后不会自动恢复运动。

## 测试与验收

测试命令见 [README](../README.md#测试)。驱动生命周期用 SDK 模拟对象测试；适配层测试覆盖官方命令构造、拒绝、取消、期限、原始反馈和 64 位参数类型；离线运动学测试直接加载随包官方库，包含有限差分和历史 IK 诊断回放。

离线测试不能替代现场通信时序和运动验收。实机按以下顺序验收：

1. 只读反馈与六维力。
2. 清错。
3. 低速单臂回位和点动。
4. 双臂与 Wuji 联合遥操作。
5. 暂停恢复、输入中断和退出。
6. 数据采集：见[数据采集参考](recording_reference.md#实机验收)。
