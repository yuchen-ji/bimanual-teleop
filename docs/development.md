# 开发参考

安装和操作见[根目录使用指南](../README.md)。本文说明数据契约、控制边界和原生接口；故障记录及测量数据单独保存在 `docs/`。

## 模块与数据

- `devices/` 负责设备连接、收流、单位转换和驱动保护；导入 Python 模块不加载设备 SDK，显式创建或启动相应设备时才加载。
- `control/arm/` 负责 Quest 映射、滤波、插值和受约束的笛卡尔伺服；`control/hand/` 负责重定向、手势与手部运行进程；`control/combined.py` 协调接合、暂停和回位。
- `cli/runtime.py` 提供两个遥操作入口共用的终端 UI 和调度；`visualization/` 提供只读查看器和 RealSense 显示。
- `tests/support/` 放置模拟设备、样本和时钟。测试不连接真实机器人。

Python 空间量使用米、弧度和秒，四元数顺序为 XYZW。`SampleHeader` 保留流、epoch、序号、接收时间、来源时间及有效性；不同设备的来源时钟不能直接相减。无效或缺失观测保持 `None`，不能补零伪造有效值。

`OperatorInput` 聚合手腕输入，`RobotState` 聚合工具实测位姿，`RobotTarget` 聚合工具目标及来源引用、创建时间和到期时间。手套骨架与 Hand2 关节命令通过设备专用类型传递。`Submission.accepted` 表示接受提交；`CommandEvent` 的发送结果不表示机器人已经到位。

## 控制生命周期

构造运行器和 `start()` 仅启动连接与收流，`engage()` 才接合。机械臂在使能前校验运动学和约束，使能后用驱动保存的实际接合样本重建伺服基准。组命令全部成功提交后才推进伺服状态；暂停、取消或异常不能提交迟到的求解结果。

机械臂循环为 200 Hz，手部默认 120 Hz。Hand2 关节状态和诊断的设备推送频率由 `feedback_hz` 指定，默认从原生 1000 Hz 限制为 200 Hz；两路必须请求相同值，设备实际量化结果写入状态日志。Quest 控制输入期限为 100 ms，机械臂命令提交期限为 50 ms，包含生成、求解和等待 SDK 接受的时间；读取缓存或循环重试不得续期。接合模式确认有独立启动期限，确认后恢复普通命令期限。慢周期跳过错过的调度点，不补发成串旧动作。

联合控制通过 `spawn` 创建 Wuji 子进程。SDK、设备接收与手部控制循环全部在子进程中运行；主进程交换生命周期请求和观察快照，不转发逐帧关节命令。快照保留原始来源时间。父进程控制心跳超时使子进程暂停；子进程、骨架、诊断或控制工作线程失联使主进程判定异常。恢复需要显式重新接合。

追踪无效、坐标原点变化、选中侧反馈异常、控制模式变化或期限超时会暂停。运动故障不会因下一包有效反馈自动清除。观察者发布失败同样不能被忽略；不接入观察者时可省略不参与控制的记录工作。

## 天机官方 SDK

[随包 SDK](../bimanual_teleop/vendor/tianji/README.md) 来自厂家提交 `02440e886fb59095711eb9ec6dcbedd8be08922a`，控制库版本 `100343014`。官方 Python 文件、Linux x86_64 `.so`、M6 4.0 模型和许可证原样打包；`manifest.json` 记录各文件 SHA-256。运行时不编译、不下载、不加载旧桥接。

`devices/tianji/sdk.py` 负责路径、完整性和类型检查，以及官方接口的成组提交。仅在项目适配层修正官方封装：整数参数使用 Linux `c_long`；`OnGetBuf` 填充官方 `DCSS`，避免转字典时的四位小数截断。传输协议及收发线程仍由厂家库管理。

一个 `ControlSDK` 拥有双臂连接；命令构造由互斥锁串行化，使用官方 `clear_set`、参数／目标接口和 `send_cmd`。等待可用槽最多 5 ms，且不超过目标有效期；构造前、等待期间和提交前检查期限与取消。未提交的失败构造会被清空。配置、接合、回位和下伺服依赖新反馈确认，控制循环不等待同步命令应答。

### 观察与命令状态

- `SDK_SUBMITTED` 表示官方 API 接受命令，不表示 UDP 已发送、控制器已接收或动作已完成。天机驱动不发出 `SENT`，不伪造发送时间、errno、字节数或丢包统计。
- `received_monotonic_ns` 为主机观察到 SDK 新反馈快照的时间，`packet_index` 为本地快照编号；二者不是底层收包时间或 UDP 包计数。
- 反馈序号逐侧检查；重复读取缓存不会刷新该侧有效期。序号跳变不能据此判定网络丢包，因为 SDK 只暴露最新快照。
- 官方库不提供待发命令取消或发送前期限拦截。已交给 SDK 的命令可能在期限之后发出；主机暂停／退出请求不能追溯撤回该命令。
- `tianji.motion_stop.v1` 保留历史字段 `last_native_call` 以兼容诊断读取；内容现在是官方 SDK 方法名及主机调用耗时。

### 单位、模型与运动学

Python 边界使用米、弧度和秒。官方关节输入／反馈为度，FK／IK 矩阵平移为毫米；几何雅可比已经是 SI 单位，线性行 m/rad、角速度行 rad/rad，不能再次除以 1000。

`TianjiKinematics` 使用 `Marvin_Kine` 的 FK、IK、雅可比和零空间接口；双侧初始化与求解共享运动学锁。默认法兰相对于各自基座，模型只允许固定 M6 4.0 内容。`--model` 仅重定位相同文件，不能换机型。离线诊断分析只加载 `libKine.so`，复用相同求解逻辑，不加载控制库。

### 回位、暂停与退出

配置等待工具、阻抗、坐标方向和速度比例的 float32 反馈匹配。接合要求新反馈 `state=3`、`impedance_type=2`。回位先用实测关节切入位置模式，确认 `state=1` 后发送最终目标；到位要求新的低速反馈、匹配的 float32 目标及关节误差不超过 0.5°。

笛卡尔暂停保持实测关节；位置运动中止使用官方 RSTA 参数。仅当停止请求被拒绝且新鲜反馈仍处于位置模式时，才采用实测位置保持。清错查询所选侧七个伺服错误码，对故障侧执行一次 RESET，再等待至少 200 ms 及新反馈确认；不使能、不运动。

退出禁止新运动提交，仅对曾受控侧请求下伺服，最多等待两秒的新 IDLE、零错误、低速且关节速度不超过 0.5°/s 的反馈。只读连接不下伺服。未确认停机时报告失败，通信中断时无法确认物理状态。

### 验证

所有 Python 测试使用 `conda run -n bimanual-teleop python -m unittest discover -s tests`。驱动生命周期使用 SDK 模拟对象；适配模块测试官方命令构造、拒绝、取消、期限、原始反馈及 64 位参数类型。离线运动学测试直接使用随包官方库，包含有限差分和历史 IK 诊断回放，不连接机器人。

实机验收顺序：只读反馈与六维力 → 清错 → 低速单臂回位／点动 → 双臂／Wuji 联动遥操作 → 暂停恢复、输入中断和退出。离线测试不能代替现场通信时序及运动验收。

## Quest 协议

[原生客户端](../quest_app/src/main/cpp/quest_capture.cpp) 通过 `QuestCapture` logcat 标签输出逐行 JSON，Python 接收器按启动会话过滤。协议版本 `v=1`。

`frame` 字段：

| 字段 | 含义 |
| --- | --- |
| `session`、`seq`、`origin` | 启动会话、帧序号和参考空间代次 |
| `query_ns`、`xr_time`、`send_ns` | 设备单调查询时刻、转换后的 OpenXR 查询时刻和输出时刻 |
| `state`、`refresh_hz` | XR 会话状态和显示刷新率 |
| `head`、`left`、`right` | 同一查询时刻的头显和 grip 位姿 |
| 位姿中的 `p`、`q`、`flags`、`active` | 米、XYZW 四元数、OpenXR 有效／追踪标志及手柄动作活跃状态 |

原始坐标为 OpenXR 的右、上、后；Python 转为前、左、上：`(x, y, z) → (-z, -x, y)`，旋转作相同基变换。缺失的位置或方向分别保留缺失，不用另一分量推定完整追踪。

`event` 包含设备时间、事件名和详情，用于报告会话状态、刷新率、错误及参考空间变化。参考空间变化按 OpenXR 生效时间切换代次，主机在此期间阻止接合。设备时钟与主机时钟未同步；接收器同时保留设备时间和主机接收时间，不以二者差值表示单向延迟。

接收器 1 秒无新帧报告收流异常；控制层另有 100 ms 输入期限和积压检查。协议不重传旧帧；恢复流后不会自动恢复运动。
